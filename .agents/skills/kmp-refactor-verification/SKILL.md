# KMP 重构验证

1. 按[验收基线](../../../docs/verification.md)选快速回归和交付前的全量 JVM 门。先查测试所在模块及 source set，再按实际任务运行。迁移后确认测试仍由正常任务执行。
2. 优先复用能断言当前行为的用例。业务规则测契约或实现，状态转移测 ViewModel 或 Store，持久性用真实本地测试库或现有重启夹具，外壳测试验证用户操作经生产路径到达目的地。仅为已有用例覆盖不到的具体回归新增测试。
3. 需要定位竞态时控制协程调度或使用现有挂起假实现，覆盖取消、成功、失败与过期结果。退出保存应能从持久记录读取最后有效页。UI 验证沿用现有语义标签、相同主题和窗口。
4. 区分本次执行、Gradle 复用与显式跳过。失败先判断是改动回归、未配置的夹具或环境限制，然后按实际结果交付。三端构建与原版脚本回归按验收文档触发。
