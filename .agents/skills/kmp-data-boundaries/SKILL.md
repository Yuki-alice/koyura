# KMP 数据边界

1. 列出调用方、当前数据源和已有领域契约。定位提交点以及读方如何看到提交后的状态。保留作品、章节与来源身份、已有偏好格式和错误语义。
2. 将可复用的业务规则和跨仓储操作放到领域侧，将 SQLDelight 查询、迁移、事务与外部数据适配放到数据侧。写入接口返回业务值或既有结果，页面在自己的状态容器中映射展示。复用已有查询和事务语义。
3. 核对重复请求、部分失败、取消和重启恢复。批量写入按现有产品语义保留原子范围。跨页面任务由会话或后台调度持有，释放页面时保留仍需完成的持久写入。
4. 迁移时为新旧入口选同一数据来源。按调用方切换，已有数据走原有格式，确需改存储时验证旧库恢复。遇到 JS 源回调、会话桥或 WebView 登录边界时补读[源兼容技能](../source-compatibility/SKILL.md)。
5. 从[验收基线](../../../docs/verification.md)运行相关行为回归，优先覆盖可观察的持久结果和失败恢复。
