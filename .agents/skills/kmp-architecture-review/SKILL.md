# KMP 架构评审

1. 固定审阅对象。对工作区区分暂存、未暂存和未跟踪文件。对分支按任务给定基准核对变更。设计文档的事实以当前生产路径、测试和 Gradle 配置为准。
2. 先从需求视角核对交互、数据兼容与阶段目标，再从实现视角查依赖方向、状态所有权、作用域、事务与公开 ABI。沿调用链追到现有消费者，尤其关注模块一迁导致的资源丢失、路由恢复、未完成的进度写入和源会话边界。
3. 优先报告可复现或有明确代码依据的阻塞项，写清触发场景、影响范围和最小修正。对待证的风险说明验证方式。避免把目录或 SDK 风格上的偏好当成回归。
4. 用[目标架构](../../../docs/application-architecture-mvvm-clean-udf.md)与[验收基线](../../../docs/verification.md)核对完成度。报告范围内的实际验证、尚未验证的路径及发现的其余旧状态入口。
