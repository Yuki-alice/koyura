## 十条设计原则

Komikku 是 Mihon / TachiyomiSY 的分支，前端基本盘是 Jetpack Compose + Material 3。它没有另起一套设计语言，而是把 M3 的**表达性（Expressive）**能力推到很满：动态取色、封面取色、双栏、自适应弹层、共享轴转场。真正形成辨识度的，是下面十条被反复执行的取舍。

| # | 原则 | 具体表现 | 复刻要点 |
| --- | --- | --- | --- |
| 01 | **内容优先，界面后退** | 阅读器默认纯黑背景、沉浸式隐藏系统栏、无边框翻页；详情页用封面模糊背景 + 渐变遮罩，让封面成为页面主色。控件只在需要时滑入。 | 先决定“内容占多少屏”，再决定控件放哪；不要先摆控件再塞内容。 |
| 02 | **双端同源，结构响应** | 平板不是“放大的手机”：导航从底栏变侧栏，设置变 master-detail，详情变双栏，弹层从 bottom sheet 变居中卡片。断点明确写在代码里（720dp 等）。 | 复用页面与组件，只切换骨架；不要在平板另写一套页面。 |
| 03 | **一套令牌，无限肤色** | 所有界面只消费 M3 语义角色（`primary` / `surfaceContainer` / `tertiary`…），因此 19 套静态主题、Monet、自定义种子、封面取色都能零改版切换。 | 组件 CSS 中不出现具体色名或 hex；只引用语义变量。 |
| 04 | **表达性，但不炫技** | 使用 `MaterialExpressiveTheme`，但圆角、字号仍克制；动效集中在 150–350ms，没有长时间装饰动画。唯一的“性格”是空状态颜文字。 | 把“个性”放在一个可控的局部（空状态、封面取色），其余保持中性。 |
| 05 | **状态即颜色** | 未读 = `secondary`、已下载 = `tertiary`、错误/NSFW = `error`、本地来源 = `tertiary` 图标；全局状态横幅用整条色带表达（隐身 = `primary`、恢复 = `error`、更新 = `tertiary`）。 | 先定义状态色表，再写组件；同一状态在所有页面保持同色。 |
| 06 | **信息密度可控** | 书架提供舒适网格 / 紧凑网格 / 列表三种模式，列数 `0` = 自适应（128dp 最小），也可固定。平板一屏可到 9 列。 | 密度是用户设置，不是断点自动决定；断点只决定骨架。 |
| 07 | **触觉与动效克制** | 只在关键动作给 haptic：收藏、拖动页码滑块、滑动删除。动效是“解释空间关系”，不是表演。 | 触觉只在“状态已改变”时触发，不在按下时泛滥。 |
| 08 | **边缘到边缘** | `enableEdgeToEdge` + 透明系统栏；顶栏在滚动前完全透明，滚动后才淡入 `surface@3dp` 背景。 | insets 由页面骨架统一消费，组件内部不重复加 padding。 |
| 09 | **可达性内建** | 48dp 最小交互尺寸、图标按钮带 `contentDescription`、长按有 Tooltip、禁用态统一 `0.38` alpha、正文对比度按 M3 角色保证。 | 不要等“无障碍适配”阶段再补；组件层就要满足最小尺寸与标签。 |
| 10 | **失败也要有人格** | 12 个随机颜文字（`(･o･;)` …）作为空状态/错误状态主视觉，尺寸 `displayMedium`，透明度 `0.78`。 | 空状态不是空白页；至少给“情绪 + 一句解释 + 一个动作”。 |

> “把 Material 3 用满，而不是把 Material 3 换掉。” —— 这套前端最准确的一句话总结

## 视觉识别四要素

| 要素           | 具体表现                                                                                                      | 不可替换的原因                                                             |
|----------------|---------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------|
| **封面驱动**   | 详情页背景 = 封面图（模糊 7dp、透明度 0.2、叠加 40% surfaceTint）+ 从上到下 transparent→background 的垂直渐变 | 它把“内容”变成“主题”，是 Komikku 与普通 M3 应用最直观的差异                |
| **双栏骨架**   | 左栏 min(宽度/2, 450dp)，右栏剩余；设置页左列表右详情                                                         | 平板体验的核心，不能靠拉伸单栏实现                                         |
| **药丸与徽标** | Nav 选中态、Tab 计数、Badge、Continue Reading 按钮、Filter 面板顶部圆角                                       | 统一由 `shapes.extraSmall/small/extraLarge` 驱动，形成“圆润但不幼稚”的观感 |
| **状态色带**   | 顶栏下方全宽横幅：Downloaded only / Incognito / Indexing / Updating / Syncing / Restoring                     | 用颜色而非图标告知全局模式，降低认知成本                                   |

## 设计意图

这十条原则的共同指向是“把视觉决策交给内容与系统，而不是交给装饰”。封面取色让每部漫画拥有自己的主色，M3 语义角色保证任何主色都不会破坏层级，响应式断点保证同一条信息在手机和平板上以不同结构出现。换句话说，Komikku 的“设计”主要发生在结构层，而不是皮肤层。

## 复刻检查清单

- [ ] 随机切换 3 套主题（Default、Monochrome、Matrix），所有页面仍能读出层级。
- [ ] 手机与平板使用同一套页面组件，仅骨架不同。
- [ ] 阅读器首屏没有常驻控件，点击/上滑才出现。
- [ ] 所有空状态都有颜文字、解释文案和至少一个出口。
- [ ] 任意页面都能指出“内容层 / 控件层 / 系统层”三层关系。
- [ ] 把封面换成纯色占位图后，页面仍然成立（说明不是靠封面图撑设计）。
