# 05 · 动效系统

> 动效总量不大（全仓约 100 处动画调用），但**每一种都对应一个明确的状态变化**。复刻时最忌讳"全部 300ms ease-in-out"——那会同时毁掉 7 类不同语义的动效。

## 5.2 逐类拆解

### ① Tab 切换：fade-through，200ms，**无缩放**

```kotlin
// HomeScreen.kt:149-157
AnimatedContent(
    targetState = tabNavigator.current,
    transitionSpec = {
        materialFadeThroughIn(initialScale = 1f, durationMillis = TabFadeDuration) togetherWith
            materialFadeThroughOut(durationMillis = TabFadeDuration)
    },
    label = "tabContent",
    contentKey = { it.key },
)
```

**关键参数**：

| 参数 | 值 | 为什么 |
|---|---|---|
| 时长 | **200ms**（`TabFadeDuration`） | 比 M3 默认的 300ms 快，工具型应用要"即时" |
| `initialScale` | **1f** | **关掉** M3 默认的 0.92 → 1.0 缩放 |
| 方向 | 双向对称 | Tab 是平级，不分前后 |
| `contentKey` | `it.key` | 保证状态保留正确 |

**为什么关缩放**：M3 的 fade-through 默认会有一个"从 92% 放大到 100%"的动作，让切换有"登场感"。Komikku 把它关掉，只剩透明度。这在截图里看不出来，但**实机上体感差异很大**——有缩放会显得"重"，没缩放才是"换了个内容"。

### ② 页面转场：shared-axis-X

```kotlin
// Navigator.kt:63-79
@Composable
fun DefaultNavigatorScreenTransition(navigator: Navigator, modifier: Modifier = Modifier) {
    val slideDistance = rememberSlideDistance()
    ScreenTransition(
        navigator = navigator,
        transition = {
            materialSharedAxisX(
                forward = navigator.lastEvent != StackEvent.Pop,
                slideDistance = slideDistance,
            )
        },
        modifier = modifier,
    )
}
```

- **前进**：新页从右滑入 + 旧页向左滑出，各有 30dp 的位移重叠
- **返回**：反向
- 时长与曲线由 `materialSharedAxisX` 内置（M3 motion，约 300ms）

**`rememberSlideDistance()`** 是 `soup.compose.material.motion` 提供的，返回约 30dp，用于让 X 轴滑动在宽屏上不至于"滑太远"。

> ⚠️ `soup.compose.material.motion` **没有 CMP 版本**。`project x` 需要用 `AnimatedContent` + 自写 `ContentTransform` 复刻：

```kotlin
// CMP 替代方案
fun sharedAxisX(
    forward: Boolean,
    slideDistance: Dp,
): ContentTransform {
    val direction = if (forward) 1 else -1
    return slideInHorizontally(
        animationSpec = tween(300, easing = FastOutSlowInEasing),
        initialOffsetX = { full -> direction * (full / 4) },
    ) + fadeIn(tween(300, delayMillis = 90)) togetherWith
        slideOutHorizontally(
            animationSpec = tween(300, easing = FastOutSlowInEasing),
            targetOffsetX = { full -> -direction * (full / 4) },
        ) + fadeOut(tween(90))
}
```

> `⚠️缺口` 上面的参数是**近似**，不是精确复刻。`soup` 库的 `materialSharedAxisX` 内部用 `slideDistance` 而非 `full/4`。若需要像素级一致，需要读 soup 的源码并把它的 `ContentTransform` 移植过来（Apache-2.0，可移植）。

### ③ 阅读器工具栏：slide + fade 双层

```kotlin
// ReaderAppBars.kt:33-34
private val readerBarsSlideAnimationSpec = tween<IntOffset>(200)
private val readerBarsFadeAnimationSpec = tween<Float>(150)
```

顶栏（`ReaderAppBars.kt:96-101`）：

```kotlin
AnimatedVisibility(
    visible = visible,
    enter = slideInVertically(initialOffsetY = { -it }, animationSpec = readerBarsSlideAnimationSpec) +
        fadeIn(animationSpec = readerBarsFadeAnimationSpec),
    exit = slideOutVertically(targetOffsetY = { -it }, animationSpec = readerBarsSlideAnimationSpec) +
        fadeOut(animationSpec = readerBarsFadeAnimationSpec),
)
```

底栏（`ReaderAppBars.kt:228-234`）：

```kotlin
enter = slideInVertically(initialOffsetY = { it }, animationSpec = readerBarsSlideAnimationSpec) +
    fadeIn(animationSpec = readerBarsFadeAnimationSpec),
exit = slideOutVertically(targetOffsetY = { it }, animationSpec = readerBarsSlideAnimationSpec) +
    fadeOut(animationSpec = readerBarsFadeAnimationSpec),
```

| 方向 | slide 起点 | 效果 |
|---|---|---|
| 顶栏进入 | `-it`（从屏幕外上方） | 下滑出现 |
| 底栏进入 | `+it`（从屏幕外下方） | 上滑出现 |

**slide 200ms、fade 150ms** 的组合：位移比透明度慢 33%，产生"先看见、再到位"的层次感。如果两者同时长，会显得"整体平移"。

侧边导航栏（`NavBarType.VerticalLeft/Right`）用 `slideInHorizontally`，参数相同。

### ④ Sheet：350ms 拖动/淡入

```kotlin
// AdaptiveSheet.kt:259
private val sheetAnimationSpec = tween<Float>(durationMillis = 350)
```

**手机**（底部抽屉）：
```kotlin
val flingBehavior = AnchoredDraggableDefaults.flingBehavior(
    state = anchoredDraggableState,
    positionalThreshold = { _: Float -> with(density) { 56.dp.toPx() } },  // 56dp 阈值
    animationSpec = sheetAnimationSpec,
)
// 打开：anchoredDraggableState.animateTo(0)
// 关闭：settle(sheetAnimationSpec) → animateTo(1)
```

**平板**（居中卡片）：
```kotlin
val alpha by animateFloatAsState(
    targetValue = targetAlpha,
    animationSpec = sheetAnimationSpec,
)
LaunchedEffect(Unit) { targetAlpha = 1f }   // 0 → 1 淡入
```

| 形态 | 属性 | 时长 |
|---|---|---|
| 手机 | 纵向位移（`AnchoredDraggable`） | 350ms |
| 平板 | 透明度 | 350ms |
| 共同 | 形状 `extraLarge`（28dp） | — |
| 共同 | 底色 `surfaceContainerHigh` | — |

> **注意**：手机 sheet **没有遮罩淡入动画**（`Dialog` 用了 `usePlatformDefaultWidth = false`，遮罩由系统 Dialog 提供）。平板也是点击遮罩关闭，但遮罩本身不做透明度动画。

### ⑤ Sheet 内导航：220+90 / 90

```kotlin
// AdaptiveSheet.kt:47-50
ScreenTransition(
    navigator = sheetNavigator,
    transition = {
        fadeIn(animationSpec = tween(220, delayMillis = 90)) togetherWith
            fadeOut(animationSpec = tween(90))
    },
)
```

| 方向 | 时长 | 延迟 | 实际可见时长 |
|---|---|---|---|
| 进入（新页） | 220ms | **90ms** | 90→310ms |
| 退出（旧页） | 90ms | 0 | 0→90ms |

**为什么延迟 90ms**：让旧页先消失（90ms），新页再淡入（从 90ms 开始）。这样两页**不会同时可见**，避免"叠影"。

### ⑥ 设置项定位高亮：200×5 + 600ms

```kotlin
// BasePreferenceWidget.kt:98-119
val highlight by animateColorAsState(
    targetValue = if (highlightFlag) {
        MaterialTheme.colorScheme.surfaceTint.copy(alpha = .12f)
    } else Color.Transparent,
    animationSpec = if (highlightFlag) {
        repeatable(
            iterations = 5,
            animation = tween(durationMillis = 200),
            repeatMode = RepeatMode.Reverse,
            initialStartOffset = StartOffset(
                offsetMillis = 600,
                offsetType = StartOffsetType.Delay,
            ),
        )
    } else tween(200),
    label = "highlight",
)
```

| 参数 | 值 |
|---|---|
| 单程 | 200ms |
| 往返次数 | 5 |
| 延迟开始 | 600ms |
| 总时长 | 600 + 200×5 = **1600ms**（代码里 `delay(3.seconds)` 是另一层控制，见下） |
| 颜色 | `surfaceTint` @ 12% alpha ↔ `Transparent` |

外层还有：
```kotlin
LaunchedEffect(Unit) {
    if (highlighted) {
        highlightFlag = true
        delay(3.seconds)   // 3 秒后停止
        highlightFlag = false
    }
}
```

所以完整行为是：**进入设置页 → 600ms 后开始闪烁 → 5 次往返（1600ms）→ 3 秒时停止**。

> 这是 Komikku 唯一的"注意力引导"动效。用于"从搜索跳到某个设置项"的场景。

### ⑦ 图片 crossfade：300ms × 动画缩放

```kotlin
// App.kt:291
crossfade((300 * this@App.animatorDurationScale).toInt())
```

| 参数 | 值 |
|---|---|
| 基础时长 | 300ms |
| 缩放 | × `animatorDurationScale`（系统"动画时长"设置） |

> **重要**：乘 `animatorDurationScale` 意味着用户在系统设置里关掉动画时，crossfade 也会变 0。这是无障碍的正确做法。复刻时必须保留这个乘法，否则"减少动画"设置会失效。

## 5.3 M3 内置、不用自己写的动画

### Elevation 动画

```kotlin
// presentation-core/.../util/Elevation.kt
private val DefaultIncomingSpec = TweenSpec<Dp>(durationMillis = 120, easing = FastOutSlowInEasing)
private val DefaultOutgoingSpec = TweenSpec<Dp>(durationMillis = 150, easing = OutgoingSpecEasing)
private val OutgoingSpecEasing = CubicBezierEasing(0.40f, 0.00f, 0.60f, 1.00f)
```

用于所有带 elevation 的组件（Button、Card、Chip）在按下/抬起时的 elevation 过渡。

### 列表项动画

```kotlin
// FastScrollAnimateItem.kt:8-10
context(itemScope: LazyItemScope)
fun Modifier.animateItemFastScroll() = with(itemScope) {
    this@animateItemFastScroll.animateItem(fadeInSpec = null, fadeOutSpec = null)
}
```

**只做位置动画，关掉淡入淡出**。原因是快速滚动时 fade 会让列表"闪"。注释里引用了 Compose issue 352584409。

### 标签区高度

```kotlin
// MangaInfoHeader.kt:377
.animateContentSize(animationSpec = spring())
```

详情页描述展开/收起时，标签区高度用**默认弹簧**。这是全仓唯一的 spring。

### 可见性展开/收起

```kotlin
// 用于：书架底栏显隐、底部动作栏、横幅、设置项启停
AnimatedVisibility(
    visible = …,
    enter = expandVertically() + fadeIn(),
    exit = shrinkVertically() + fadeOut(),
)
```

默认参数（约 300ms）。用于：
- 书架底栏（`HomeScreen.kt:125-129`）
- 底部动作栏（`MangaBottomActionMenu.kt:84-88`）
- 全局横幅（`Banners.kt:105-110`）
- 设置项启停（`PreferenceItem.kt:44-52`）

> 注意书架底栏用的是 `expandVertically()` **不带 fade**（`HomeScreen.kt:127-128`），而动作栏/横幅带 fade。细节差异，复刻时照抄。

## 5.4 触觉反馈

全仓共 **20 处** `performHapticFeedback` 调用，只有 **2 种类型**：

| 类型 | 次数 | 触发场景 |
|---|---:|---|
| `HapticFeedbackType.LongPress` | 16 | 长按进入多选、长按动作栏按钮确认、长按下载按钮 |
| `HapticFeedbackType.TextHandleMove` | 2 | 拖动阅读器页码滑块（横/竖两种布局） |
| `HapticFeedbackConstants.LONG_PRESS`（View 层） | 2 | 阅读器 Webtoon/Pager 长按（旧 View 实现） |

支持性的调用点（Presentation 层 13 处，其余在 ScreenModel/Viewer）：

| 场景 | 代码 |
|---|---|
| 书架长按进入多选 | `LibraryTab.kt:332` |
| 详情页长按章节 | `MangaScreen.kt:281` |
| 批量收藏选择 | `BulkFavoriteScreenModel.kt:417` |
| 源浏览长按 | `BrowseSourceScreen.kt:377` |
| 迁移长按 | `MigrateMangaScreen.kt:323` |
| 更新错误列表长按 | `LibraryUpdateErrorScreen.kt:224`、`LibraryUpdateErrorUiItem.kt:145` |
| 更新列表长按 | `UpdatesUiItem.kt:289` |
| 底部动作栏长按确认 | `MangaBottomActionMenu.kt:200` |
| 章节下载按钮长按 | `ChapterDownloadIndicator.kt:249` |
| 设置滑块拖动 | `SettingsItems.kt:196` |
| 阅读器页码滑块 | `ChapterNavigator.kt:148, 263` |

> **规律**：`LongPress` 只用在"长按 = 进入某种模式 / 确认危险操作"，`TextHandleMove` 只用在"滑块精细选择"。**普通点击没有任何触觉**。
>
> `🎯推断` 这是克制的表现：普通点击加触觉会让应用"话多"；长按（危险）和滑块（精细）才是触觉真正有用的地方。

## 5.5 什么**没有**动效

同样重要。以下都是"静态"的：

| 位置 | 说明 |
|---|---|
| 导航栏/轨图标 | 只有 Tab 图标有动画矢量；AppBar 的返回/搜索/更多都是静态 `Icon` |
| 封面加载 | 有 crossfade，但**没有 scale/parallax** |
| 列表滚动 | 无 parallax、无 sticky header 缩放 |
| FAB | 只有 `animateFloatingActionButton`（M3 的展开/收起），无自定义 |
| 卡片点击 | 无 scale 反馈，只有 ripple |
| 主题切换 | `DynamicMaterialExpressiveTheme(animate = true)` 会做颜色插值，但那是 materialkolor 的行为，不是 Komikku 自己写的 |
| 页面背景 | 详情页封面背景是静态 `blur(7.dp)` + `alpha(0.2f)`，无动态模糊 |
| 进度 | 下载进度环用 `ProgressIndicatorDefaults.ProgressAnimationSpec`（M3 默认） |

## 5.6 动效与"减少动画"设置

Komikku 对系统无障碍设置的响应：

| 设置 | 响应 | 代码 |
|---|---|---|
| 动画时长缩放 = 0 | Coil crossfade 变 0 | `App.kt:291` |
| 动画时长缩放 = 0 | Compose 的 `animate*` 自动变 0（框架行为） | — |
| 动画时长缩放 = 0 | `AnimatedVectorDrawable` 自动跳帧 | 框架行为 |
| 移除动画（Remove animations） | 同上 | — |

> `⚠️缺口` 代码里**没有**显式的 `LocalMotionDurationScale` 检查。依赖框架的自动处理。`project x` 在 CMP 上需要确认各平台都正确响应（Compose Desktop 的 `LocalMotionDurationScale` 行为与 Android 不同）。

## 5.7 CMP 实现对照

| Komikku | CMP 可用性 | 方案 |
|---|---|---|
| `materialFadeThroughIn/Out`（soup） | ❌ 无 | 自写：`fadeIn(tween(200)) togetherWith fadeOut(tween(200))`（`initialScale=1f` 意味着本来就只是 fade） |
| `materialSharedAxisX`（soup） | ❌ 无 | 自写 `ContentTransform`（见 §5.2 ②） |
| `rememberSlideDistance()`（soup） | ❌ 无 | 自定常量 30dp |
| `AnimatedImageVector` + `rememberAnimatedVectorPainter` | ✅ CMP 1.13 | 但 Android XML 动画矢量需重做为 Compose 资源 |
| `AnimatedVisibility` | ✅ | 直接用 |
| `animateFloatAsState` / `animateColorAsState` | ✅ | 直接用 |
| `AnimatedContent` | ✅ | 直接用 |
| `Crossfade`（Coil） | ✅ | Coil 3 支持 CMP |
| `LocalMotionDurationScale` | ✅ CMP | 但桌面/iOS 行为需验证 |

### 最小可行动效集（如果时间紧）

按"复刻相似度 / 实现成本"排序，前 4 个必做：

| 优先级 | 动效 | 理由 |
|---|---|---|
| P0 | Tab fade-through 200ms（无缩放） | 每次切 Tab 都能感受到 |
| P0 | 页面 shared-axis-X | 每次进出页面 |
| P0 | 阅读器工具栏 slide+fade | 阅读时最高频 |
| P1 | Sheet 350ms + 内部导航 220+90/90 | 筛选、排序常用 |
| P1 | 图片 crossfade 300ms×scale | 封面加载 |
| P2 | 设置项高亮闪烁 | 只有"从搜索跳转"时出现 |
| P2 | 列表项 `animateItem` 无 fade | 快速滚动时才有差异 |

## 设计意图（`🎯推断`）

1. **为什么 Tab 切换关掉缩放**：缩放暗示"内容登场"，fade 才是"内容替换"。工具型应用不需要戏剧性。
2. **为什么阅读器 slide 比 fade 慢**：位移是"物理"的，透明度是"光学"的。位移稍慢会让工具栏看起来"从边缘滑出来"，而不是"凭空出现"。
3. **为什么 sheet 是 350ms 而不是 M3 的 300ms**：拖动关闭需要一点"惯性余量"，350ms 让手指离开后仍有可感知的减速。
4. **为什么只给长按和滑块加触觉**：普通点击加触觉会让应用"话多"；长按（危险）和滑块（精细）才是触觉真正有用的地方。
5. **为什么列表项关掉 fade**：快速滚动时，fade 会让每个新项"闪一下"，视觉噪声极大。

## 复刻检查清单

- [ ] Tab 切换 200ms fade-through，**`initialScale = 1f`**（无缩放）
- [ ] 页面 push/pop 用 X 轴 shared-axis，前进/返回方向相反
- [ ] 阅读器顶栏 `-it` 进入、底栏 `+it` 进入，slide 200 / fade 150
- [ ] Sheet 350ms，手机位移、平板 alpha
- [ ] Sheet 内导航 220ms + 90ms delay 进入 / 90ms 退出
- [ ] 图片 crossfade **乘 `animatorDurationScale`**
- [ ] 列表项用 `animateItem(fadeInSpec = null, fadeOutSpec = null)`
- [ ] 详情页标签区 `animateContentSize(spring())`
- [ ] 书架底栏显隐**不带** fade，动作栏/横幅**带** fade
- [ ] 触觉只在长按确认与滑块拖动
- [ ] 没有任何装饰性 / 循环 / 视差动画
- [ ] 系统"移除动画"时所有动效归零
